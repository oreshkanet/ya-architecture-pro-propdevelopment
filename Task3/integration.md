# Требования к внешним интеграциям

## Требования к безопасности

1. Защита передаваемых данных:
   - Использование TLS 1.2+ (рекомендуется TLS 1.3) для всех сетевых взаимодействий;
   - Шифрование чувствительных данных (например, PII, токены, credentials);
   - Запрет на передачу учётных данных и ключей в URL (только в заголовках или теле запроса).
2. Управление учётными данными и секретами:
   - Хранение ключей, токенов и паролей в защищённых vault-системах (например, HashiCorp Vault);
   - Регулярная ротация ключей (минимум 1 раз в 90 дней, или по политике инцидентов);
   - Использование короткоживущих токенов (если поддерживается).
3. Ограничение доступа:
   - Принцип минимальных привилегий: интеграция получает только те права, которые необходимы для выполнения задачи;
   - IP-ограничения и "белые листы" IP: ограничивать входящие/исходящие соединения известными IP-адресами;
   - Rate limiting и circuit breaker на стороне API-шлюза или микросервиса.
4. Аудит и мониторинг:
   - Логирование всех входящих и исходящих интеграционных вызовов;
   - Отслеживание аномальных паттернов: повышенная частота запросов, неавторизованные попытки доступа, неожиданные объёмы данных;
   - Обязательная интеграция с SIEM или аналогичной системой мониторинга безопасности (по мере масштабирования).
5. Валидация и санитизация данных:
   - Строгая валидация входных данных по схеме (OpenAPI/Swagger, JSON Schema);
   - Защита от инъекций (SQLi, XSS, SSRF) на уровне шлюза и сервисов;
   - Отказ в обработке запросов с неподдерживаемыми media-types, кодировками или структурами.
6. Соблюдение регуляторных требований:
   - Соответствие GDPR/ФЗ‑152 при обработке персональных данных (анонимизация/псевдонимизация при необходимости);
   - Прозрачность: поставщик интеграции должен документировать, какие данные передаются, где хранятся, как обрабатываются.

## Протоколы аутентификации и авторизации

- Аутентификация внешних систем: OAuth 2.0 Client Credentials Flow;
- Авторизация внешних систем: OAuth 2.0 Scopes / Claims

## Взаимодействие с внешними системами

При интеграции систем умного дома предполагается использование персональных данных пользователей:

- Биометрические данные;
- Номера автомобилей.

Для описания взаимодействия с системой партнёра можно рассмотреть несколько кейсов.

### Регистрация нового собственника

1. Система умного дома отправляет запрос системе партнёра на добавление нового собственника;
2. Система умного дома передаёт биометрические данные системе партнёра (либо формирование биометрических данных происходит на стороне партнёра) с привязкой к внешнему токену пользователя;
3. Система партнёра привязывает к внешнему токену пользователя биометрические данные.

### Открытие дверей по биометрическим данным

1. Система партнёра присылает запрос системе умного дома на разрешение открытия двери с токеном пользователя;
2. Система умного дома проверяет по токену собственника и доступность помещения;
3. Система умного дома отдаёт ответ в формате "Да/Нет";
4. Система партнёра автоматически запрещает доступ, если биометрические данные не зарегистрированы.

### Открытие шлагбаума по номеру автомобиля

1. Система партнёра присылает запрос системе умного дома на разрешение открытия шлагбаума с номером авто;
2. Система умного дома проверяет по номеру авто собственника и доступность парковки;
3. Система умного дома отдаёт ответ в формате "Да/Нет";
4. Система партнёра автоматически запрещает доступ, если биометрические данные не зарегистрированы.
